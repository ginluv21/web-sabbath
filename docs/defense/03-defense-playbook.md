# Web Sabbath: сценарий защиты лабораторной 4

Этот документ можно перечитать непосредственно перед защитой. Он описывает порядок показа, короткое выступление, технические объяснения и действия при проблемах. Это подсказка для понимания и честной демонстрации, а не инструкция скрывать чужой код или помощь при разработке.

## 1. Самое главное за минуту

Проект: Web Sabbath, конструктор домашних страниц в стиле начала 2000-х.

Сейчас: два типа блоков - заголовок и текст. Можно добавлять, изменять и удалять. Предпросмотр и счётчик обновляются сразу.

Технологии: JavaScript, React, React DOM, Vite. NES.css предоставляет готовые стили. Собственная логика лежит в usePageBlocks.

Главная мысль защиты: один массив blocks является источником данных для редактора, предпросмотра и счётчика. Дети вызывают функции, переданные через props, и эти функции обновляют общее состояние.

Для «отлично»: показать собственный хук с useState, рабочий алиас @, повторное использование Button из shared и все базовые критерии.

Нет: API, авторизации, сохранения после перезагрузки, экспорта, drag-and-drop. Лаба 5 - следующий этап, её не выдаём за готовую.

## 2. Что подготовить заранее

1. Открыть папку проекта. Пока локальный путь /home/badim/front/muse; название папки не изменилось после переименования репозитория.
2. Проверить ветку lab-4-geocities и наличие всех нужных исходников. До согласованного коммита часть файлов может быть отмечена U. Для сдачи исходники должны быть зафиксированы и отправлены, а не только лежать на компьютере.
3. Если зависимости уже установлены, снова npm install не требуется. На новом компьютере после получения исходников выполнить npm install.
4. Выполнить npm run build и npm run lint. Успешная сборка не равна полному тесту поведения, поэтому пройти короткую демонстрацию ниже.
5. Выполнить npm run dev и оставить этот терминал открытым. Перейти по адресу, который напечатал Vite.
6. Открыть в редакторе App.jsx, usePageBlocks.js, BlockEditor.jsx, PageEditor.jsx, PagePreview.jsx, shared/ui/Button.jsx и vite.config.js.
7. Подготовить README с источниками и таблицей критериев.
8. Проверить размер окна: на узком экране панели стоят вертикально, на широком рядом. Это нормальное адаптивное поведение.
9. Сделать пробный показ: добавить два типа блоков, отредактировать и удалить. После этого обновить страницу, чтобы начать защиту с пустого редактора.

Команды из папки проекта:

```bash
npm run build
npm run lint
npm run dev
```

Терминал занят сервером после dev - это нормально. Ctrl+C останавливает его. Не закрывай сервер перед демонстрацией.

## 3. Готовое вступление на 40-60 секунд

> Мой проект называется Web Sabbath. Это учебный конструктор персональных веб-страниц в стиле старого интернета. Пользователь не пишет HTML, а добавляет заголовки и текстовые блоки, редактирует их содержимое и сразу видит результат справа.
>
> Для лабораторной 4 я ограничил объём двумя типами блоков. Приложение разделено на компоненты. Состояние хранится в собственном хуке с useState и используется несколькими компонентами. Данные и функции передаются через props. Также настроен алиас @ и вынесена общая кнопка в shared.
>
> В оформлении использованы готовые CSS-элементы NES.css и ретро-референсы, которые указаны в README. Сейчас покажу пользовательский сценарий и затем путь данных в коде.

Говори своими словами. Если преподаватель попросил сразу код, не продолжай вступление поверх его вопроса.

## 4. Демонстрация интерфейса: конкретные действия

| Шаг | Действие | Что объяснить и проверить |
| --- | --- | --- |
| 1 | Показать пустую страницу | В редакторе и предпросмотре понятные сообщения, счётчик 0 |
| 2 | Нажать «+ Заголовок» | Создаётся объект блока, справа появляется заголовок, счётчик 1 |
| 3 | Изменить заголовок на «Фан-клуб совы» | Поле управляемое; предпросмотр получает новое состояние сразу |
| 4 | Нажать «+ Текст» | Добавляется другой тип, в редакторе textarea, справа абзац |
| 5 | Ввести две строки текста | Переносы видны в абзаце благодаря white-space: pre-wrap |
| 6 | Добавить ещё один заголовок | Один компонент повторно используется; ID разные даже для одинаковых типов |
| 7 | Изменить последний заголовок | Первый не меняется: обновление идёт по ID, не по типу |
| 8 | Очистить одно поле | Пустая строка не вызывает ошибку и остаётся редактируемой |
| 9 | Удалить средний блок | Остальные сохраняют свои тексты и стабильные ключи, счётчик уменьшается |
| 10 | Удалить оставшиеся блоки | Возвращаются пустые сообщения и счётчик 0 |

Не перегружай демонстрацию. Шаги 1-5 показывают основной сценарий; 6-10 показывают обработку крайних случаев. Если времени мало, достаточно отдельно показать удаление последнего блока и объяснить независимость ID.

Питомец в шапке - статичное изображение и подпись. Можно упомянуть его как маскот, но не показывать как функциональную часть критерия React.

## 5. Показ кода в правильном порядке

### Сначала App.jsx: общая схема

Покажи вызов:

```jsx
const { blocks, addBlock, updateBlock, deleteBlock } = usePageBlocks()
```

Объясни: «Хук вызывается один раз в общем родителе. Дальше тот же массив передаётся в PageEditor и PagePreview, а счётчик показывает его длину». Найди JSX этих компонентов и покажи props.

### Затем usePageBlocks.js: состояние и три действия

Покажи useState([]), затем функции добавления, изменения и удаления.

Короткая речь:

> blocks первоначально пустой. При добавлении создаётся объект с уникальным ID, типом и текстом. Функциональный setter получает актуальный предыдущий массив. Spread добавляет блок, map заменяет текст только у совпавшего ID, filter удаляет нужный блок. Прежний массив не меняю напрямую.

Если спросят, где находится состояние, уточни: файл хука отдельный, но useState связан с вызовом этого хука в экземпляре App. Не называй его глобальной переменной.

### Затем BlockEditor.jsx: callback ребёнка

Покажи onChange поля:

```jsx
onChange={(event) => onUpdate(block.id, event.target.value)}
```

Объясни: «Поле передаёт ID и новое значение функции родителя. Функция обновляет массив. value получает обновлённый text». Затем покажи аналогичный callback удаления.

### Затем PageEditor.jsx и PagePreview.jsx: map и key

Объясни: «Редактор повторяет BlockEditor через map. key берётся из ID, который создан один раз. Предпросмотр проходит по тому же массиву и выбирает h3 или p по типу. Индекс массива ключом не используем, потому что блоки можно удалять».

### Затем shared/ui/Button.jsx: переиспользование

Покажи children, callback, дополнительный className и ...props. Покажи два места использования: добавление в BlockToolbar и удаление в BlockEditor.

Фраза:

> Общая кнопка не зависит от сущности блока. Она получает подпись и действие извне. nes-btn даёт готовое оформление NES.css, а React-компонент организует повторное использование.

### Затем vite.config.js и jsconfig.json: алиас

Покажи @ в настройке и реальный импорт `@/shared/ui/Button.jsx`.

Фраза:

> Vite реально разрешает алиас при запуске и сборке. jsconfig сообщает тот же путь редактору для навигации. Мы пишем JavaScript, несмотря на название compilerOptions.

### В конце main.jsx и index.html: запуск

Если преподаватель просит объяснить основу, покажи цепочку root - createRoot - App. Vite обслуживает файлы локально, а не хранит сайт на внешнем сервере. Это пояснение помогает отличить свою логику от автоматически созданной инфраструктуры.

## 8. Если что-то пошло не так

### localhost не открывается

Скажи: «Проверю, запущен ли локальный сервер разработки». Посмотри терминал, запусти npm run dev из правильной папки, используй напечатанный адрес. Если порт занят, не обещай, что обязательно 5173: ориентируйся на вывод Vite. Не выдавай недоступность локального сервера за проблему GitHub.

### После обновления исчезли блоки

Это ожидаемо: сохранение не реализовано. Объясни ограничение и добавь блоки заново. Не называй это autosave или backend.

### Преподаватель просит объяснить незнакомую строку

Найди её в гайде 02, затем вернись к исходнику и объясни своими словами: вход, действие, результат. Если пока не понимаешь, скажи это и разбери спокойно. Не выдумывай механизм.

### Сборка упала после правки

Сначала прочитай сообщение: файл, строка, причина. Проверь импорт, скобки, путь @. После исправления повтори сборку и пользовательский сценарий. Не запускай npm install наугад при любой ошибке.

### В jsconfig есть предупреждение

Сообщение об устаревшем baseUrl исправлено: опция удалена, paths указывает @/* на ./src/*. Если редактор всё ещё показывает старое сообщение, сохрани файл и дай ему перечитать настройки; при необходимости перезапусти окно редактора. Если появилась другая диагностика, прочитай её точный текст в Problems. Конфигурация редактора и результат сборки - разные проверки.

### Говорят, что дизайн не нравится

Объясни, что стилизация намеренная и не является техническим критерием сама по себе. Покажи читаемые поля, работающие кнопки, адаптивность и обработку пустого состояния. Дизайн можно менять без переписывания состояния.

## 9. Следующее развитие: что говорить про лабораторную 5

> Следующим этапом добавлю каталог ретро-шаблонов через API. Небольшой сервер будет возвращать несколько шаблонов. React загрузит их через единый Axios instance. Сделаю собственный useTemplates с данными, загрузкой, ошибкой и reload, покажу пустой список и повторный запрос. Request-interceptor будет логировать метод и адрес. Сохранение страниц на сервер и авторизацию в этот этап не включаю.

Позднее можно добавить изображения, изменение порядка, применение шаблонов, localStorage и экспорт. Это отдельные согласованные функции, не обещание уже готового полного редактора.
