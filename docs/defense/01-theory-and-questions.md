# Web Sabbath: теория и вопросы на защите

Этот гайд относится к лабораторной 4. Лабораторная 5 описана только как следующий этап. Вопросы ниже - тренировочная симуляция, а не обещание, что преподаватель спросит именно их. Учить нужно смысл и уметь находить соответствующее место в коде.

Этот раздел можно читать как небольшую учебную главу, без подготовки. Сначала разберём, что вообще происходит на компьютере и в браузере. Затем перейдём к языкам и React. Все примеры служат объяснению; добавлять их в приложение отдельно не нужно.

### А. Что такое фронтенд и что делает браузер

Фронтенд - часть приложения, с которой человек взаимодействует в браузере: надписи, формы, кнопки, расположение областей и реакция на действия. Браузер не просто показывает картинку. Он разбирает HTML, применяет CSS, выполняет JavaScript и обрабатывает события пользователя.

В нашем проекте фронтенд - весь текущий редактор Web Sabbath. Пользователь нажимает «+ Заголовок», получает поле, вводит текст и видит результат. Всё это происходит в браузере.

Backend - отдельная серверная программа, которая может хранить данные, проверять доступ и отдавать ответы по API. В лабораторной 4 такой программы у нас нет. Vite запускает сервер разработки, но это ещё не написанная нами серверная логика приложения.

Представь приложение как мастерскую. HTML описывает, где столы и инструменты. CSS задаёт их внешний вид. JavaScript определяет, что происходит при использовании инструмента. React помогает организовать эту мастерскую в повторяемые части и связать её вид с данными.

### Б. HTML, CSS и JavaScript решают разные задачи

HTML описывает структуру и смысл элементов. Заголовок, абзац, поле, кнопка и область страницы - разные элементы. Их выбирают не только по внешнему виду: `<button>` изначально предназначен для действия, `<input>` для ввода.

```html
<h1>Мой сайт</h1>
<p>Добро пожаловать!</p>
<button type="button">Добавить текст</button>
```

CSS задаёт оформление. Селектор выбирает элементы, а свойства описывают их вид:

```css
button {
  color: navy;
  background-color: gold;
}
```

В этом примере все подходящие кнопки получат тёмно-синие буквы и золотой фон. CSS не создаёт блок в массиве и не удаляет его. Он только изменяет представление.

JavaScript выполняет действия и вычисления:

```js
const title = 'Мой сайт'
const count = 2 + 1
```

Первая строка сохраняет текст, вторая вычисляет число. В React JavaScript также выбирает, какую разметку вернуть и как обновить данные после события.

### В. Путь от адреса до страницы

Когда ты открываешь адрес, браузер обращается к серверу. Сервер возвращает HTML и другие ресурсы: JavaScript, CSS, изображения. Браузер получает ресурсы и собирает видимую страницу.

При разработке нашего проекта сервер запускает Vite. Адрес `http://127.0.0.1:5173/` состоит из частей:

- `http` - протокол обращения.
- `127.0.0.1` - этот же компьютер, также известный как loopback.
- `5173` - порт, на котором слушает сервер.
- `/` - путь запрошенной страницы.

Название вкладки задаёт `<title>` в index.html. Оно не переименовывает адрес и не создаёт домен. Название репозитория GitHub тоже не меняет localhost.

Если закрыть Vite, локальный сервер остановится. Уже открытая страница иногда ещё остаётся на экране, но её перезагрузка не сможет получить файлы с остановленного сервера. Для настоящего размещения нужен отдельный шаг публикации сборки на хостинге.

### Г. React, React DOM, Vite, Node.js и npm

React - библиотека JavaScript. Она помогает описывать интерфейс компонентами и связывать результат с текущими данными. React не заменяет язык JavaScript и не хранит данные в базе автоматически.

React DOM - пакет, который соединяет React с браузерным DOM. У нас `createRoot(...).render(...)` подключает App к элементу root.

Vite - инструмент работы над проектом. Он запускает сервер разработки, обрабатывает импорты и JSX, быстро отражает изменения исходников и собирает файлы для размещения. Поэтому «сайт лежит в Vite» - неточная формулировка. Сайт состоит из исходников; Vite их обслуживает и собирает.

Node.js исполняет JavaScript вне браузера. Здесь он нужен, чтобы запускать Vite и связанные инструменты. То, что Node.js установлен, не означает, что в проекте уже есть backend.

npm устанавливает пакеты и запускает команды из package.json. Пакет - набор файлов с кодом и метаданными. Один пакет не равен одному файлу и может зависеть от других пакетов.

```text
npm create vite@latest -> создаёт шаблон проекта
npm install            -> скачивает зависимости
npm run dev            -> запускает локальную разработку
npm run build          -> создаёт dist
npm run lint           -> проверяет исходники статически
```

`npm run dev` ищет свойство dev в scripts и выполняет записанную там команду. Это не произвольное магическое слово React.

### Д. Почему файлов так много и какие нужны тебе

Файлы проекта делятся на четыре группы.

**Наши исходники:** App, компоненты, хук, CSS. Здесь сосредоточено поведение Web Sabbath. Именно их ты объясняешь подробно.

**Настройки:** package.json, vite.config.js, jsconfig.json, .oxlintrc.json, .gitignore. Они объясняют инструментам, как работать с проектом. Обычно настроек немного, но они не менее важны для запуска.

**Чужие зависимости:** node_modules. Их создал npm при установке. Не нужно учить сотни файлов React и Vite для защиты этого редактора.

**Сгенерированный результат:** dist. Его создала сборка. Это готовые ресурсы браузера, не место для ручного изменения исходников.

JSON - текстовый формат данных: объекты, массивы, строки, числа, true/false и null. Файл `.json` обычно читается инструментом, а не исполняется как функция. Ключи и строки заключают в двойные кавычки. В обычном JSON нельзя вставлять комментарии и завершающие запятые.

package-lock.json особенно большой, потому что описывает точные версии и дерево пакетов. Он помогает воспроизвести установку. Его не нужно переписывать вручную.

### Е. Переменные и значения JavaScript

Переменная - имя, по которому обращаются к значению. В нашем коде чаще всего используется const:

```js
const title = 'Фан-клуб совы'
const count = 3
const isEmpty = false
```

Здесь есть строка, число и логическое значение. Строка содержит текст, число участвует в вычислениях, boolean задаёт «да/нет».

`const` запрещает переприсвоить имя другой величине. Но объект или массив, записанный в const, технически ещё может изменяться. Поэтому const не является гарантией неизменяемости состояния React.

`null` обычно используют как явно выбранное отсутствие значения. `undefined` означает, что значение отсутствует, например свойство не передали. В нашем хранилище блоков начальное значение не null, а пустой массив `[]`.

`===` сравнивает значения строго, без автоматического преобразования типов. Поэтому строка `'3'` и число `3` не считаются одним и тем же. `!==` проверяет строгое неравенство.

### Ж. Объект - одна сущность, массив - список сущностей

Объект объединяет связанные свойства:

```js
const block = {
  id: 'abc',
  type: 'heading',
  text: 'Моя страница',
}
```

Доступ к свойству через точку: `block.text` возвращает строку `Моя страница`. ID идентифицирует запись, type описывает разновидность, text хранит содержимое.

Массив хранит последовательность:

```js
const blocks = [
  { id: 'a', type: 'heading', text: 'Мой сайт' },
  { id: 'b', type: 'text', text: 'Добро пожаловать!' },
]
```

`blocks.length` равно 2. `blocks[0]` означает первый объект; индекс начинается с нуля. Порядок массива задаёт порядок блоков в редакторе и предпросмотре.

ID и индекс - разные понятия. После удаления первого блока второй получает индекс 0, но его ID остаётся b. Поэтому операции над редактируемыми блоками используют ID.

### З. Функции, параметры, аргументы и return

Функция описывает действие, которое можно выполнить позже:

```js
function greet(name) {
  return 'Привет, ' + name
}

const message = greet('Сова')
```

`name` - параметр в объявлении. `'Сова'` - аргумент конкретного вызова. return возвращает вычисленный результат вызывающему коду. `message` получает строку `Привет, Сова`.

Объявить функцию и вызвать её - не одно и то же. `greet` обозначает функцию, `greet('Сова')` выполняет её сейчас. Эта разница особенно важна при передаче обработчиков кнопке.

Стрелочная функция - другая форма записи:

```js
const double = (number) => number * 2
```

Если после стрелки стоит выражение без тела `{}`, оно возвращается автоматически. Если есть тело, return нужно писать явно, когда нужен результат:

```js
const double = (number) => {
  return number * 2
}
```

В `onClick={() => onAdd('text')}` функция без параметров вызывает другую функцию с определённым аргументом. Она выполнится только тогда, когда React обработает клик.

### И. Деструктуризация, rest и spread

Деструктуризация извлекает значения из объекта или массива:

```js
const { text, type } = block
const [first, second] = ['a', 'b']
```

Это сокращённый способ создать несколько переменных, а не создание новой базы данных. В параметрах компонента `function PagePreview({ blocks })` извлекает свойство blocks из переданного объекта props.

Spread разворачивает элементы массива или свойства объекта:

```js
const nextBlocks = [...blocks, newBlock]
const updatedBlock = { ...block, text: 'Новый текст' }
```

Первая строка создаёт новый массив с ещё одним блоком. Вторая создаёт новый объект с прежними свойствами и заменённым text. Копирование поверхностное: вложенные объекты не копируются рекурсивно. Для нашей плоской структуры этого достаточно.

Rest собирает оставшиеся значения. В Button запись `...props` в параметрах собирает не перечисленные ранее свойства. А `{...props}` на HTML-кнопке разворачивает их обратно в атрибуты. Одинаковые три точки выполняют разную роль в зависимости от места записи.

### К. map, filter и условные выражения

`map` получает функцию и строит новый массив результатов:

```js
const numbers = [1, 2, 3]
const doubled = numbers.map((number) => number * 2)
```

Результат `[2, 4, 6]`. Сам map не сокращает число элементов. В нашем редакторе он либо заменяет нужный объект, либо превращает объекты блоков в JSX-компоненты.

`filter` оставляет элементы, для которых проверка вернула true:

```js
const remaining = blocks.filter((block) => block.id !== deletedId)
```

Если ID совпал с удаляемым, проверка false, объект не попадёт в новый массив. Исходный массив filter не удаляет на месте.

Тернарный оператор выбирает значение:

```js
const label = type === 'heading' ? 'Заголовок' : 'Текст'
```

Слева от `?` условие, между `?` и `:` результат при true, после `:` результат при false. Так выбираем текст, тип поля и пустое сообщение в JSX.

### Л. Компонент: функция, описывающая часть интерфейса

Компонент в нашем проекте - функция, возвращающая JSX:

```jsx
function Welcome() {
  return <p>Добро пожаловать!</p>
}
```

Компонент можно использовать как `<Welcome />`. Имя начинается с большой буквы: React отличает его от встроенного HTML-тега `<p>`.

Декомпозиция означает разделение общей задачи на части с понятными обязанностями. App собирает страницу. BlockToolbar предлагает действия. BlockEditor отвечает за один блок. PageEditor отображает список редакторов. PagePreview отображает результат. Button предоставляет общую кнопку.

Это не означает «создать максимум файлов». Файл отделяют тогда, когда у части есть самостоятельная обязанность или повторное использование. Мы не создаём отдельный файл для каждой надписи и каждого добавленного блока.

Один компонент может иметь много экземпляров. Десять блоков не требуют десяти файлов BlockEditor: React вызывает одну функцию для десяти разных объектов данных.

### М. JSX: как JavaScript описывает разметку

JSX похож на HTML, но допускает выражения JavaScript:

```jsx
<p>Блоков: {blocks.length}</p>
```

Внутри фигурных скобок вычисляется значение. Здесь берётся число элементов массива. В кавычках записывают постоянный текст атрибута, в фигурных скобках передают значение:

```jsx
<input className="block-input" value={block.text} />
```

`className` связывает элемент со стилем. `value` берётся из данных. Это разные задачи.

В JSX HTML-теги закрываются, включая одиночные `<img />`, `<input />`, `<br />`. Большая область обычно возвращает один общий корневой элемент. Несколько соседей можно обернуть в Fragment `<>...</>`, если не нужен лишний DOM-элемент.

JSX не исполняется браузером в исходном виде как отдельный стандарт HTML. Его преобразует инструментальная цепочка. Поэтому проекту и нужен настроенный запуск/сборка, а не двойной клик по App.jsx.

### Н. Props: вход компонента

Props - объект входных значений. Родитель передаёт их в JSX:

```jsx
<PagePreview blocks={blocks} />
```

Дочерняя функция получает это значение:

```jsx
function PagePreview({ blocks }) {
  // здесь доступен переданный массив
}
```

Имя свойства согласовано с обеих сторон. Если родитель передаст pages, а ребёнок попробует читать blocks, получится отсутствие нужного значения.

Через props можно передавать строки, числа, массивы, объекты и функции. Props доступны для чтения. Менять объект состояния родителя напрямую из ребёнка неправильно: для запроса изменения передаём callback.

`children` - особое обычное свойство содержимого между тегами компонента. В `<Button>Удалить блок</Button>` оно содержит подпись. Button может показывать любую переданную подпись и не обязан знать, где используется.

### О. Состояние: то, что интерфейс должен помнить

Обычная функция вызывается, создаёт локальные переменные и возвращает результат. React-компонент может вызываться много раз. Если каждый раз писать `const blocks = []`, компонент каждый раз вычислял бы интерфейс на основе пустого массива.

`useState` позволяет React сохранить значение между отрисовками конкретного экземпляра:

```js
const [blocks, setBlocks] = useState([])
```

blocks - текущий снимок состояния. setBlocks - функция запроса обновления. Начальный `[]` используется при создании состояния. Это не команда очистить массив на каждом вызове компонента.

После обновления React снова вычисляет компоненты с новым снимком. Это не обязательно пересоздание всего DOM и не перезагрузка страницы.

Не следует представлять setter как немедленное присваивание переменной. Внутри уже работающего обработчика blocks относится к той отрисовке, для которой обработчик создан. React обрабатывает обновления и выдаёт новые значения в следующей отрисовке.

### П. Почему состояние изменяем через новые массивы

В React данные состояния не следует мутировать напрямую. Нам нужен новый результат, а не незаметная правка уже использованного объекта.

```js
setBlocks((current) => [...current, block])
```

React передаёт current как актуальное предыдущее состояние. Функция возвращает новый массив. Такая форма полезна, когда следующее значение зависит от предыдущего и обновления могут попасть в очередь.

При редактировании используем новый массив и новый объект только нужной записи:

```js
setBlocks((current) => current.map((block) => (
  block.id === id ? { ...block, text } : block
)))
```

Для остальных записей сохраняем прежние объекты. Неизменяемость не требует копировать весь проект или все картинки после каждого символа.

Почему это читаемо: по коду можно понять, какое действие выполняется. Spread добавляет, map заменяет, filter удаляет. Старое состояние остаётся понятным снимком, который мы не переделали задним числом.

### Р. События и callbacks: действия идут обратно к родителю

Данные идут сверху вниз. Событие сообщает, что пользователь хочет изменить эти данные.

```jsx
<Button onClick={() => onAdd('heading')}>+ Заголовок</Button>
```

Здесь callback - переданная функция. Button не сам решает, куда добавить объект. Он вызывает действие, полученное от родителя.

Плохая запись для этого случая:

```jsx
<Button onClick={onAdd('heading')}>+ Заголовок</Button>
```

Она вызывает onAdd прямо во время вычисления JSX. Вместо передачи будущего действия получается его текущий результат. Это может приводить к лишним обновлениям или циклу отрисовок.

Внутри Button допустимо `onClick={onClick}`: там уже лежит готовая функция, она не вызывается в этой строке.

### С. Управляемые поля: одна строка, два места отображения

Управляемое поле получает value из состояния:

```jsx
<input
  value={block.text}
  onChange={(event) => onUpdate(block.id, event.target.value)}
/>
```

Пользователь вводит символ. Браузер создаёт событие. event.target.value содержит всю новую строку поля. Обработчик передаёт эту строку и ID в updateBlock. React обновляет состояние, и поле получает новое value.

Предпросмотр читает тот же block.text. Поэтому его не нужно обновлять отдельным обращением к DOM. Мы не ищем правый абзац через document.querySelector после каждого символа.

`defaultValue` устроен иначе: задаёт исходное значение неуправляемого поля. Для нашего общего источника данных удобнее value + onChange.

Пустая строка тоже является значением. Если пользователь удалил весь текст, сохраняем `''`, не возвращаем автоматически старый текст. Объект блока остаётся и по-прежнему считается в счётчике.

### Т. Один источник данных и подъём состояния

Если редактор и предпросмотр хранили бы каждый свой массив, их пришлось бы отдельно синхронизировать. Они могли бы расходиться. Поэтому состояние расположено в общем родителе и передаётся нужным областям.

```text
           App + usePageBlocks
            /       |       \
      панель     редактор   предпросмотр
      onAdd      onUpdate   blocks
                 onDelete
```

Это называется подъёмом состояния к общему родителю. Сам хук вынесен в файл, но его вызов находится в App. Состояние связано именно с этим экземпляром App.

Счётчик не хранит отдельное число. Он показывает `blocks.length`. Производное значение лучше вычислить из существующих данных, чтобы не забыть обновить его после удаления.

### У. Собственный хук и общая кнопка

Хук usePageBlocks собирает связанную логику: состояние списка и три операции. Он возвращает объект, который App деструктурирует. Компонент страницы становится короче, но механизм React не меняется.

Хук - не глобальный singleton. Два отдельных вызова usePageBlocks получили бы два отдельных состояния. Для общего массива вызываем его один раз и передаём результат детям.

Имя начинается с use. Внутри используются React-хуки, поэтому вызов должен находиться на верхнем уровне компонента или другого хука. Нельзя вызывать хук только по клику или только при определённом условии: порядок вызовов должен сохраняться.

shared/Button решает другую задачу: повторяет внешний вид и HTML-структуру кнопки. Он возвращает JSX, не хранит список блоков. Можно поменять стиль общей кнопки в одном месте и получить изменение у добавления и удаления.

Хук повторно использует логику. Компонент повторно использует часть интерфейса. Утилита выполняет обычное вычисление и не обязана участвовать в React.

### Ф. Списки, key и стабильность элементов

Когда массив превращается в список JSX, каждому соседнему элементу нужен стабильный key:

```jsx
blocks.map((block) => (
  <BlockEditor key={block.id} block={block} />
))
```

React использует key, чтобы сопоставить элементы между отрисовками. Если удалён первый блок, второй должен остаться вторым объектом с прежним ID, даже если визуально стал первым.

ID создаётся один раз в addBlock. Генерировать новый key при каждом map нельзя: для React это выглядело бы как появление заново других элементов. Индекс массива тоже плох для списка с удалениями, потому что он меняется при сдвиге соседей.

key не передаётся как обычное свойство компоненту. BlockEditor читает block.id, а не props.key.

### Х. Импорты, модули и алиасы

Файл-модуль может экспортировать значение, а другой файл его импортировать:

```js
export default Button
```

```js
import Button from '@/shared/ui/Button.jsx'
```

`export default` - главный экспорт файла. Импорт useState из React использует фигурные скобки, потому что берёт именованный экспорт.

Относительный путь начинается с `./` или `../`. `./` - текущая папка, `../` - выше. При большом числе вложений длинные пути становятся неудобными.

Алиас @ в нашем проекте обозначает src. Он сокращает путь и сохраняет его смысл при разной глубине папок импортирующих компонентов.

Есть две настройки:

- vite.config.js задаёт реальное разрешение пути при запуске и сборке.
- jsconfig.json сообщает редактору тот же путь для навигации и подсказок.

Устаревший baseUrl убран. paths указывает `@/*` на `./src/*` относительно jsconfig.json. Звёздочка подставляет оставшуюся часть импорта. Настройка не добавляет TypeScript в наш код.

### Ц. CSS: как читать оформление нашего сайта

CSS-правило состоит из селектора и списка свойств:

```css
.block-editor {
  padding: 12px;
  background-color: #fffef0;
}
```

Точка означает класс. Правило выбирает элементы с className="block-editor". padding задаёт внутренний отступ, background-color фон.

margin - внешнее расстояние до соседей. border - рамка. padding - пространство внутри рамки. `box-sizing: border-box` помогает включить рамку и padding в заданную ширину, чтобы элементы не стали неожиданно шире.

Специфичность определяет, какое правило побеждает при конфликте. `.builder .workspace-panel` более специфично, чем `.workspace-panel`. Порядок подключения тоже имеет значение при одинаковых условиях. Поэтому NES.css подключён первым, затем наши CSS.

Flex удобно располагает элементы в строку или колонку: например, логотип и сову. Grid задаёт сетку трёх рабочих областей. `minmax(0, 1fr)` позволяет колонке делить оставшуюся ширину и не запрещает ей сжиматься.

Media query включает правила при определённой ширине экрана. До 800px сетка становится одноколоночной. Это не новый компонент и не запрос API.

Звёзды - radial-gradient, золото логотипа - несколько text-shadow, серебристая рамка - ridge, кривая плашка - transform: rotate(...). Сова - отдельный PNG. Эти способы нужно различать: не всё на странице нарисовано картинками, и не всё создано CSS.

### Ч. DOM, повторная отрисовка и StrictMode

DOM - структура элементов документа в памяти браузера. В ней есть узлы заголовков, полей, кнопок и текста. React DOM вносит в неё изменения на основе возвращённого JSX.

Вычисление нового интерфейса и применение изменений к DOM - не одно и то же действие. React может снова вызвать компонент, но это не означает, что браузер пересоздал всю страницу с нуля.

StrictMode в main.jsx включает дополнительные проверки разработки. React может повторно вызывать некоторые функции, чтобы выявить нечистое поведение. Поэтому updater должен вычислять результат из current, а не менять внешние данные.

Это не объяснение «двойного срабатывания любой кнопки». ID нового блока у нас создаётся до вызова updater, а updater возвращает новый массив без внешних побочных эффектов.

### Ш. Доступность, семантика и текст пользователя

Семантические элементы помогают понять назначение частей. main - основное содержимое, header - шапка, section - тематическая область, article - отдельный блок, button - действие.

label связан с полем через htmlFor и id. У каждого блока своё имя поля, поэтому клик по подписи относится к правильному input/textarea.

aria-labelledby связывает область с её заголовком. alt описывает сову для случая, когда картинка не отображается или используется экранный диктор. :focus-visible делает положение клавиатурного фокуса заметным.

Строки пользователя выводятся как текст JSX. Ввод `<b>Привет</b>` не превращается в исполняемую HTML-разметку. В текущем проекте нет dangerouslySetInnerHTML. Это конкретное свойство вывода текста, а не обещание, что будущие загрузки изображений и экспорт автоматически безопасны.

### Щ. Git, GitHub и состояние рабочей папки

Git хранит коммиты - снимки отслеживаемых файлов. Ветка указывает на коммиты. Рабочая папка содержит текущие файлы, включая ещё не добавленные в историю.

Поэтому фраза «файлы уже есть в ветке» может быть неточной до коммита: они находятся в рабочем дереве при выбранной ветке, но пока не вошли в её историю.

GitHub хранит отправленные коммиты и позволяет открыть Pull Request. Он не получает файлы автоматически при сохранении в редакторе. Нужно согласовать коммит и отправить его.

U - untracked, M - modified. Эти отметки не являются диагностикой JavaScript. `.gitignore` исключает node_modules и dist из списка новых файлов. История уже отслеживаемых файлов автоматически от этого не переписывается.

В нашем процессе main - принятые изменения. Лаба 4 выполняется в lab-4-geocities. После завершения открываем PR, владелец мержит вручную и сохраняет ветку.

### Ъ. Как проверяют проект и почему проверок несколько

Сборка проверяет, что инструменты могут обработать импорты, JSX, CSS и создать выходные ресурсы. Она не гарантирует правильность каждого действия пользователя.

Lint анализирует код по правилам, например корректность вызовов хуков. Он не кликает кнопки и не доказывает, что предпросмотр совпадает с текстом.

Проверка в браузере проходит сценарии: пустая страница, добавление, изменение, удаление, узкий экран. Мы проверили несколько блоков одного типа, пустую строку, удаление среднего и последнего блока.

Эти проверки дополняют друг друга. Не стоит говорить «всё проверено», если запускалась только сборка. В нашей работе отдельно описаны фактические проверки и ограничения.

### Ы. API и дальнейшее развитие: пока только представление

API - согласованный способ общения программ. Для лабы 5 браузер будет запрашивать список шаблонов по HTTP и получать JSON. Это другой JSON: ответ сервера, а не файл настроек редактора.

Запрос может занимать время, завершиться ошибкой или вернуть пустой массив. Поэтому интерфейс должен показывать загрузку, ошибку с повтором и пустое состояние.

В будущей лабе планируем Axios instance, API-модуль, useTemplates и useEffect. Сейчас они не реализованы. Сохранение страницы пользователя на сервер и логин - отдельные задачи.

useEffect нужен для синхронизации с внешней системой, например загрузки данных. Обычный подсчёт blocks.length и отрисовку предпросмотра не требуется переносить в useEffect: они вычисляются из текущего состояния.

### Ь. Один полный маршрут действия в Web Sabbath

Разберём ввод буквы в заголовок как цепочку причин, а не список терминов.

1. App уже получил blocks из usePageBlocks и передал его PageEditor и PagePreview.
2. PageEditor через map создал BlockEditor для нужного объекта.
3. BlockEditor показывает input с value={block.text}.
4. Пользователь вводит новую букву. Браузер вызывает onChange.
5. Обработчик читает всю строку event.target.value и вызывает onUpdate с ID.
6. onUpdate связан с updateBlock, который вернул хук.
7. updateBlock через setBlocks и map создаёт новую версию массива.
8. React получает новое состояние и заново вычисляет интерфейс.
9. Input получает новое value, PagePreview выводит новый text.
10. Число объектов не изменилось, поэтому счётчик остался прежним.

В этой цепочке нет прямого изменения правого DOM-элемента, запроса backend и записи файла. Всё объясняется общим состоянием и передачей данных.

### Ю. Небольшие упражнения для понимания

**Упражнение 1.** Есть два объекта в blocks. Пользователь добавляет ещё один текстовый блок. Сколько будет полей, сколько элементов предпросмотра, какое значение счётчика?

Ответ: три редактора блоков, три соответствующих элемента предпросмотра, счётчик 3. Состояние массива изменилось один раз, его используют несколько мест.

**Упражнение 2.** У первого заголовка ID a, у второго b. Меняем text блока b. Какой изменится?

Ответ: только объект, у которого block.id === b. Тип heading не используется как идентификатор, поэтому одинаковые типы не мешают независимому редактированию.

**Упражнение 3.** Пользователь полностью очистил textarea. Нужно ли удалять сам блок?

Ответ: нет. Пустая строка хранится как text, поле остаётся. Удаление - отдельное действие кнопкой. Счётчик не меняется от очистки текста.

**Упражнение 4.** Удалили единственный блок. Что получает filter?

Ответ: новый пустой массив. Редактор и предпросмотр выбирают пустые ветки условного JSX, счётчик равен нулю.

**Упражнение 5.** Почему нельзя создать ID в key={crypto.randomUUID()} при каждой отрисовке?

Ответ: ключ каждый раз новый, React не сможет стабильно сопоставлять записи. ID создают при добавлении и хранят в данных.

**Упражнение 6.** Что произойдёт после обновления вкладки?

Ответ: приложение запускается заново с useState([]). Блоков нет. React state не является постоянным сохранением.

**Упражнение 7.** Зачем Button вынесен в shared, а PageEditor нет?

Ответ: Button универсален, принимает подпись и действие. PageEditor знает структуру блоков и относится к задаче конструктора.

## 1. Что мы сделали

Web Sabbath - учебный конструктор домашних страниц. Пользователь добавляет заголовки и текстовые блоки, меняет содержимое, удаляет блоки. Рядом сразу виден результат. Внешний вид напоминает сайты начала 2000-х, но управление простое. Сова - статичная картинка, а не отдельная система питомцев.

Сейчас нет API, авторизации, сохранения, экспорта и перетаскивания. После обновления страницы блоки исчезают. Это ограничение выбранного объёма лабы, а не скрытая готовая функция.

Данные одного блока:

```js
{ id: 'уникальная-строка', type: 'heading', text: 'Мой сайт' }
```

`id` различает блоки, `type` выбирает способ отображения, `text` содержит пользовательский текст. Тип `text` означает обычный абзац. В редакторе заголовок редактируется через input, абзац через textarea. В предпросмотре это h3 и p.

## 2. React, Vite, браузер: кто за что отвечает

| Название | Роль здесь | Не путать с |
| --- | --- | --- |
| JavaScript | Язык функций, массивов, условий и обработчиков | React - библиотека, не язык |
| React | Библиотека построения интерфейса из компонентов и состояния | Не база данных и не хостинг |
| React DOM | Связывает React с DOM браузера; createRoot запускает приложение | Не отдельный сервер |
| JSX | Синтаксис разметки в JavaScript-файлах | Похож на HTML, но это не обычный HTML-файл |
| Vite | Инструмент разработки и сборки: запускает локальный сервер, обрабатывает JSX и импорты | Не место постоянного размещения сайта |
| Node.js | Среда JavaScript вне браузера, здесь запускает npm и Vite | В лабе 4 не написан собственный backend |
| npm | Устанавливает пакеты и запускает scripts из package.json | Не React и не веб-сервер сам по себе |
| HTML | Начальная страница index.html и элементы интерфейса | JSX преобразуется инструментами до исполнения |
| CSS | Цвета, размеры, расположение, рамки | Не изменяет массив блоков |
| NES.css | Подключённые готовые CSS-классы контейнеров и кнопок | Не содержит нашу логику React |
| Git | Локальная история изменений и ветки | Не GitHub |
| GitHub | Удалённый репозиторий и Pull Request | Не автоматически запущенный сайт |

Адрес `http://127.0.0.1:5173/` означает: браузер обращается к Vite на этом компьютере. 127.0.0.1 - адрес текущего устройства, 5173 - порт сервера. Такой адрес на другом компьютере будет указывать на другой компьютер, а не на наш сайт. После остановки Vite страница уже не сможет нормально перезагружаться с этого адреса.

### Что создаётся автоматически

`npm create vite@latest` создаёт шаблон файлов. `npm install` создаёт node_modules и обновляет package-lock.json. `npm run build` создаёт dist. `npm run dev` запускает сервер разработки. Сотни файлов пакетов не являются сотнями написанных нами компонентов. В Git передаются исходники, конфигурация и lock-файл; node_modules и dist исключены .gitignore.

Файл package.json ещё содержит имя `muse`. Это старое техническое имя npm-проекта. Имя репозитория и название вкладки уже Web Sabbath. Это не влияет на логику редактора и не означает, что открыто другое приложение.

| Критерий | Место | Что сказать |

| Проект через Vite | package.json, vite.config.js | Основа создана официальным генератором, затем демо заменено |
| Компоненты | src/components | Панель, редактор, один блок и предпросмотр имеют отдельные задачи |

Наличие файла с именем хука само по себе не закрывает критерий: хук реально импортирован и вызван в App. Аналогично алиас реально используется, а Button реально используется в разных компонентах.

## 4. Основные вопросы и ответы

### 1. Какова тема проекта?

Конструктор персональных страниц в ретро-стиле. Текущая версия строит страницу из заголовков и абзацев. Дальше он развивается по лабораторным, а не всеми возможностями сразу.

### 2. Почему React?

Нужны повторяющиеся блоки и несколько областей, которые показывают одни данные. React позволяет описывать интерфейс компонентами и обновлять его через состояние. Кроме того, это технология задания.

### 3. Что такое компонент?

В нашем проекте это JavaScript-функция с именем с большой буквы, возвращающая JSX. Например, PagePreview получает blocks и описывает предпросмотр. Компонент задаёт часть интерфейса; React вызывает его при отрисовке.

### 4. Почему компоненты с большой буквы?

Так JSX различает компонент и встроенный HTML-тег. `<Button />` - наша функция, `<button>` - встроенный элемент браузера.

### 5. Чем JSX отличается от HTML?

JSX находится внутри JavaScript. Значения вставляются в фигурных скобках, CSS-класс задаётся через className, связь label с полем через htmlFor. Теги должны закрываться. JSX преобразуется инструментами сборки, браузер не читает App.jsx как обычный HTML.

### 6. Зачем return?

Возвращает описание интерфейса из функции компонента. Скобки после return позволяют удобно разместить многострочный JSX. Они сами не создают HTML-элемент.

### 7. Что такое props?

Входные данные компонента. В `<PagePreview blocks={blocks} />` родитель передаёт массив. `function PagePreview({ blocks })` извлекает свойство из объекта props. Дочерний компонент не должен менять props напрямую.

### 8. Что такое children?

Содержимое между открывающим и закрывающим тегами компонента. В `<Button>+ Текст</Button>` children - строка `+ Текст`. Button помещает её внутрь обычного button.

### 9. Что такое состояние?

Данные, которые React сохраняет между вызовами конкретного экземпляра компонента. В нашем случае blocks. Обновление состояния позволяет React заново вычислить нужный интерфейс.

### 10. Что возвращает useState?

Пару: текущее значение и функцию обновления. `[blocks, setBlocks]` - деструктуризация массива. `[]` внутри useState задаёт первоначально пустой список.

### 11. Почему нельзя просто let blocks = []?

При повторном вызове функции локальная переменная создавалась бы заново. Изменение обычной переменной само по себе не сообщило бы React, что нужно обновить интерфейс. useState даёт сохранение значения и механизм обновления.

### 12. Где состояние, если useState не написан в App?

App вызывает usePageBlocks. Вызов useState внутри этого хука связан с экземпляром App. Отдельный файл хука не превращает состояние в глобальное хранилище.

### 13. Два вызова usePageBlocks разделят один массив?

Нет. Разные вызовы хука имеют независимое состояние. Поэтому здесь вызываем хук один раз в общем родителе и передаём его результат детям.

### 14. Что такое собственный хук?

Функция, имя которой начинается с use и которая использует React-хуки для повторного использования логики. usePageBlocks организует состояние и операции над блоками. Он не возвращает JSX.

### 15. Чем хук отличается от утилиты?

Утилита может, например, просто преобразовать строку. Её можно вызвать в обычной функции. Наш хук вызывает useState, поэтому подчиняется правилам React и должен вызываться в компоненте или другом хуке.

### 16. Какие правила вызова хуков?

Вызывать на верхнем уровне компонента или другого хука, не внутри условий, циклов, вложенных обработчиков. В App вызов стоит до return и выполняется в одинаковом порядке при каждой отрисовке.

### 17. Почему updateBlock не называется useUpdateBlock?

Это обычная функция-обработчик, возвращённая хуком. Она не вызывает новые хуки. Имя use для неё не нужно.

### 18. Что такое callback?

Функция, которую передали другому коду для последующего вызова. App передаёт updateBlock как onUpdate. Когда пользователь вводит текст, BlockEditor вызывает onUpdate с ID и новым текстом.

### 19. Как ребёнок меняет состояние родителя?

Не получает прямой доступ к внутренней переменной родителя. Вызывает переданную функцию. Эта функция вызывает setBlocks, и React обновляет состояние.

### 20. Зачем onClick={() => onAdd('text')}?

Передаём функцию, которая вызовет onAdd с типом text при клике. Если написать onClick={onAdd('text')}, вызов произойдёт во время отрисовки вместо клика.

### 21. Почему onClick={onClick} в Button без стрелки?

Button уже получает готовую функцию. Он просто передаёт её обычному HTML-button. Дополнительные аргументы на этом уровне не нужны.

### 22. Что значит event.target.value?

event - объект события. target - поле, в котором произошло изменение. value - его текущая строка. Она передаётся в onUpdate вместе с ID блока.

### 23. Почему поле называется управляемым?

У него есть value={block.text}, а изменение обрабатывается через onChange. Значение приходит из состояния React. Пользователь вводит символ, обработчик обновляет состояние, после чего поле получает новое value.

### 24. Что произойдёт без onChange?

Поле с заданным value не будет нормально редактироваться: значение по-прежнему задаёт состояние, которое не обновляется. React также может предупредить о поле только для чтения.

### 25. Почему не defaultValue?

defaultValue задаёт начальное значение неуправляемого поля. Здесь нужен постоянный общий источник данных для поля и предпросмотра, поэтому используем value и onChange.

### 26. Почему при вводе меняется предпросмотр?

PageEditor и PagePreview получают один blocks. onUpdate создаёт новый массив в состоянии App. После повторного вычисления компонентов оба получают обновлённые данные. Отдельного массива предпросмотра нет.

### 27. Что такое однонаправленный поток данных?

Данные передаются от App детям через props. События возвращаются вызовами callbacks. Мы не читаем текст прямо из DOM предпросмотра и не синхронизируем две отдельные копии массива.

### 28. Как добавляется блок?

Создаётся объект с ID, type и начальным text. `setBlocks((current) => [...current, block])` создаёт новый массив со старыми элементами и новым в конце.

### 29. Почему setBlocks принимает функцию?

Новая версия зависит от предыдущей. React передаёт updater-функции актуальное предыдущее значение, учитывая очередь обновлений. Это не прямое синхронное присваивание переменной blocks.

### 30. Почему нельзя blocks.push(block)?

push меняет существующий массив. Мы сохраняем неизменяемость состояния: создаём новый массив. Прямое изменение состояния без setter не является правильным способом запросить отрисовку.

### 31. Что делает spread [...current, block]?

Разворачивает элементы current в новый массив и добавляет block. Это поверхностное копирование: старые объекты внутри массива не клонируются, но в этом действии их и не требуется менять.

### 32. Что делает map в updateBlock?

Проходит по массиву и возвращает новый массив той же длины. Если ID совпадает, возвращает новый объект с новым text. Если нет, возвращает прежний объект. Остальные блоки сохраняют свои данные.

### 33. Зачем { ...block, text }?

Копирует свойства блока и заменяет text. ID и type сохраняются. Сам исходный объект не меняется.

### 34. Что делает filter при удалении?

Создаёт массив только из блоков, чей ID не равен удаляемому. При удалении последнего блока получается [], и компоненты показывают пустые состояния.

### 35. Зачем ID и key?

ID адресует конкретный блок при редактировании и удалении. key помогает React сопоставлять элементы списка между отрисовками. Он стабилен, потому что создаётся один раз при добавлении блока.

### 36. Почему key не индекс?

После удаления среднего блока индексы остальных сдвигаются. Стабильный ID лучше описывает идентичность элемента и предотвращает неправильное сопоставление элементов списка.

### 37. Почему crypto.randomUUID не вызывается внутри map?

Тогда key менялся бы при каждой отрисовке. Мы создаём ID в addBlock и храним его в данных. crypto - браузерный API; localhost подходит для его использования.

### 38. Получает ли BlockEditor key как обычный prop?

Нет. key использует React. Сам ID доступен компоненту через переданный block.id.

### 39. Почему ternary, а не if?

Выражение `условие ? вариант1 : вариант2` можно вставить в JSX. Оно выбирает пустое сообщение или список, input или textarea. if тоже допустим в JavaScript вне этого места, но здесь ternary короче.

### 40. Почему не создаём кнопку как блок страницы?

Потому что текущий минимум содержит только два типа. Кнопки здесь управляют редактором. Новый тип блока согласуем позднее.

### 41. Что произойдёт при пустом тексте?

Состояние хранит пустую строку. Блок остаётся в редакторе, его можно дописать или удалить. Предпросмотр не заменяет пустую строку старым текстом. Это допустимый пользовательский сценарий.

### 42. Можно ввести HTML?

Можно ввести строку `<b>Привет</b>`, но JSX покажет её как текст, а не исполнит как разметку. Мы не используем dangerouslySetInnerHTML и не строим DOM из пользовательской HTML-строки. Это не утверждение о безопасности всего будущего проекта.

### 43. Зачем white-space: pre-wrap?

В абзацах предпросмотра сохраняет переносы строк пользователя, но допускает перенос длинных строк по ширине. Без этого обычный HTML сворачивает часть пробелов и переносов.

### 44. Зачем overflow-wrap: anywhere?

Позволяет перенести очень длинное слово или URL в узком предпросмотре. Иначе текст мог бы выйти за ширину панели.

### 45. Что такое shared?

Папка общих переиспользуемых элементов. Это выбранная организация проекта, а не специальная папка React. Button не знает, что такое heading, ID блока или удалить страницу. Текст и поведение получает через props.

### 46. Почему не вынести весь редактор в shared?

Редактор связан с сущностью блока и задачей конструктора. Общая кнопка пригодна в других разделах. shared не означает склад всех компонентов.

### 47. Зачем ...props в Button?

Rest собирает остальные свойства в объект. Spread на HTML-button передаёт их дальше, например disabled или aria-label. Это расширяет возможности общей кнопки, не заставляя перечислять все HTML-атрибуты вручную.

### 48. Зачем className = ''?

Значение по умолчанию не даёт вставить слово undefined в строку классов, если дополнительный класс не передали. Основной класс nes-btn остаётся всегда.

### 49. Что такое алиас?

Короткое имя пути импорта. Здесь @ соответствует папке src. Вместо длинного относительного пути используем `@/shared/ui/Button.jsx`.

### 50. Зачем два файла для алиаса?

vite.config.js настраивает реальную обработку импортов при запуске и сборке. jsconfig.json сообщает редактору, куда ведёт путь, для навигации и подсказок. paths сопоставляет @/* с ./src/* относительно файла конфигурации. Устаревший baseUrl убран, он не нужен для этой настройки. Один только jsconfig не настраивает сборщик.

### 51. Что делают fileURLToPath и import.meta.url?

import.meta.url - URL текущего модуля vite.config.js. new URL('./src', import.meta.url) находит src относительно конфигурации. fileURLToPath переводит file-URL в файловый путь для алиаса, без ручной привязки к /home/badim.

### 52. Что делает StrictMode?

В режиме разработки включает дополнительные проверки React. Может повторно вызывать некоторые функции и updater-функции, чтобы обнаруживать нечистый код. Это не намеренное двойное добавление блока при каждом клике. ID создаётся до updater, а updater строит результат без внешних побочных эффектов.

### 53. Где запускается приложение?

index.html содержит div с id root и загружает main.jsx. createRoot находит этот div и render показывает App внутри него. App подключает хук и дочерние компоненты.

### 54. Что такое DOM?

Объектное представление HTML-страницы в браузере. React рассчитывает интерфейс и через React DOM обновляет нужные DOM-элементы. Мы не редактируем их вручную через innerHTML.

### 55. Что происходит при повторной отрисовке?

React снова вызывает функции компонентов и получает новое описание интерфейса. Это не обязательно полное удаление и создание всей страницы. React сопоставляет результат и применяет необходимые изменения.

### 56. Где сохранение данных?

Только в состоянии работающего приложения. Нет localStorage, файла проекта и базы данных. Обновление страницы создаёт новый экземпляр приложения с пустым массивом. Для лабы 4 сохранение не требуется.

### 57. Сайт лежит в Vite?

Нет. Исходники лежат в папке проекта. Vite временно обслуживает их при разработке и собирает dist для размещения. Реального внешнего хостинга в этой работе не настроено.

### 58. Что такое npm run build?

Запускает команду build из package.json, здесь vite build. Она создаёт dist с HTML, CSS, JavaScript и картинками для браузера. Это не автоматическая публикация на GitHub Pages.

### 59. Что такое npm run lint?

Запускает oxlint: статически проверяет код по правилам. Это полезная проверка, но она не доказывает, что все пользовательские сценарии работают. Поэтому мы ещё проверяли их в браузере.

### 60. private: true значит приватный GitHub?

Нет. Это настройка npm, защищающая от случайной публикации пакета в registry. Репозиторий GitHub публичный, это отдельная настройка.

### 61. Почему есть @types/react, если нет TypeScript?

Эти пакеты поставил шаблон. Они дают сведения о типах для инструментов и подсказок редактора. Наши файлы - .js и .jsx; TypeScript-код мы не пишем. Наличие @types не превращает проект в TypeScript.

### 62. Что написано самостоятельно, а что взято?

Шаблон и конфигурационные заготовки создал Vite. Сценарий визуального конструктора изучен в website-builder. Готовые CSS-классы - NES.css. Наши компоненты, состояние, callbacks, алиас, компоновка и тексты созданы для учебного проекта. Сова обработана imagegen из предоставленной картинки. Не нужно утверждать, что вся библиотека или иллюстрация нарисованы вручную.

### 63. Можно ли показать исходники референса как свой код?

Нет. Показываем его как технический референс, а наши файлы как собственную реализацию сценария. Дословного переноса кода конструктора пока не было. Источники указаны в README.

### 64. Что такое .gitignore?

Список путей, которые Git обычно не предлагает добавлять как новые файлы. В нём node_modules, dist, логи. Уже отслеживаемый файл не исчезает из истории только потому, что его вписали в .gitignore.

### 65. Что означает U рядом с файлом?

Обычно в редакторе Git это untracked: файл ещё не добавлен в историю. M - изменённый отслеживаемый файл. Это не ошибка React. Значок `1` у jsconfig может означать диагностику редактора; её точный смысл нужно читать в Problems, по скриншоту его нельзя определить.

### 66. Чем ветка отличается от папки?

Ветка - ссылка на последовательность коммитов, а не отдельная копия папки. Наши текущие незакоммиченные файлы пока находятся в рабочем дереве. Только после коммита они становятся частью истории ветки.

### 67. Что такое Pull Request?

Предложение слить изменения ветки в main на GitHub. После завершения и проверки лабы открываем PR. Владелец мержит вручную, ветку не удаляем.

### 68. Почему не используем state manager?

Состояние маленькое и имеет одного общего родителя. Достаточно useState и props. По заданию сторонние менеджеры состояния пока не нужны.

### 69. Как адаптируется интерфейс?

CSS Grid задаёт три колонки. При ширине до 800px media query оставляет одну колонку. minmax(0, 1fr), min-width: 0 и перенос длинного текста помогают не распирать панели.

### 70. Зачем label и aria-labelledby?

label связывает название с полем по уникальному inputId. aria-labelledby связывает область с её заголовком. Это помогает понять интерфейс в том числе без визуального оформления. role=status отмечает строку с количеством блоков как статус.

## 5. Вопросы следующей лабы: только план

**Есть ли API сейчас?** Нет. Для лабы 5 планируем GET /api/templates с несколькими ретро-шаблонами.

**Что покажем в интерфейсе?** Список шаблонов, загрузку, ошибку с повтором, пустой ответ. Применение шаблона к странице не требуется для минимальных критериев и обсуждается отдельно.

**Зачем Axios, а не fetch?** Для оценки «отлично» задание требует Axios instance и интерсептор. Планируем единые baseURL/заголовки и логирование метода/адреса запроса.

**Что такое useEffect?** Хук синхронизации с внешними системами. В будущей лабе он запустит загрузку при открытии компонента. В текущей собственной логике он не используется; не следует показывать план как реализованную функцию.

**Что такое backend?** Серверная программа с маршрутом, который возвращает данные. Vite в лабе 4 - сервер разработки, а не написанный нами API шаблонов.

## 6. Симуляция разговора от начала до конца

**Преподаватель:** Что показываете?

**Студент:** Web Sabbath - конструктор домашних страниц. Для лабы 4 сделал два типа блоков, редактирование, удаление и предпросмотр. Оформление стилизовано под начало 2000-х.

**Преподаватель:** Покажите работу.

**Студент:** Сейчас список пуст. Добавляю заголовок, абзац и ещё один заголовок. Изменяю первое поле - справа результат меняется. Удаляю средний блок - остальные сохраняют свои данные. Удаляю последний - возвращается пустое состояние.

**Преподаватель:** Где состояние?

**Студент:** В usePageBlocks вызывается useState. Сам хук вызывается один раз в App. Результат передаётся компонентам через props.

**Преподаватель:** А как дочерний компонент меняет его?

**Студент:** Вот onChange в BlockEditor: он вызывает onUpdate с ID и строкой. В App onUpdate связан с updateBlock из хука. Там setter и map создают новое состояние.

**Преподаватель:** Объясните map и spread.

**Студент:** map сохраняет длину массива и заменяет только объект с нужным ID. Spread копирует его свойства в новый объект, text переопределяет прежний текст. Остальные объекты возвращаются как были.

**Преподаватель:** Почему хук, а не просто функция?

**Студент:** Он вызывает useState, хранит логику состояния в рамках React и должен вызываться по правилам хуков. Обычная утилита не имеет этого ограничения.

**Преподаватель:** Что в shared?

**Студент:** Общая кнопка. Она принимает children, callback и дополнительные атрибуты, ничего не знает про типы блоков. Используется и в панели добавления, и при удалении.

**Преподаватель:** Что скопировали?

**Студент:** Подключил NES.css для готовых стилей. Сценарий конструктора изучал в открытом репозитории. Наши компоненты и обработчики реализованы отдельно. Источники и авторство библиотеки указаны в README и THIRD_PARTY_NOTICES.

**Преподаватель:** Сохранение есть?

**Студент:** Нет. Сейчас только React state, при обновлении список пуст. Это оговорённый минимум. В следующей лабе подключу API каталога шаблонов.

### Исправление настройки алиаса

В jsconfig.json удалён baseUrl, вызвавший сообщение редактора об устаревшей опции. Теперь paths содержит явный путь ./src/*. Сам алиас @ и импорты сохранились. Рекомендация - удалить baseUrl и записать явный префикс в paths - описана в [официальных заметках TypeScript 6.0](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-6-0.html#deprecated---baseurl).
