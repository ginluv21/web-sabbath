# Web Sabbath

Учебный проект на React и JavaScript. Конструктор персональных веб-страниц в стиле старого интернета. Название приложения - Web Sabbath, репозиторий - `web-sabbath`.

> INTO THE WEB
>
> Личные страницы, громкие цвета и немного цифрового шума.

Название - отсылка к [Black Sabbath](https://www.blacksabbath.com/). Подзаголовок Into the Web обыгрывает название [Into the Void](https://www.youtube.com/watch?v=KSSEzWXqGKY). Это музыкальное вдохновение для собственного учебного проекта.

Make the Internet Ugly Again.

Проект развивается по лабораторным работам. Ниже описан план, а не список уже реализованных возможностей. Сейчас в рабочей папке остаётся предыдущий прототип министерства; его замену будем выполнять отдельными согласованными шагами.

## Идея

Пользователь создаёт нарочито нелепую домашнюю страницу: фан-клуб кота, личный дневник или сайт коллекционера носков. Визуально это старый интернет: яркие цвета, цветные окна, объёмные кнопки, пиксельные детали и надписи Under Construction. При этом действия редактора должны оставаться понятными.

Технический референс: [Website Builder от Akshara Varshney](https://github.com/aksharavars/website-builder).

В изученной версии референса есть блоки заголовка, текста и изображения, редактирование, удаление, перестановка через DnD Kit, живой предпросмотр, localStorage и экспорт HTML. Основная реализация находится в одном App.jsx. Берём сценарий работы редактора и изучаем устройство данных; нашу учебную реализацию разделяем на компоненты по требованиям преподавателя. Tailwind и DnD Kit для лабы 4 не нужны. Файл лицензии в изученной версии не найден; перед дословным заимствованием исходников вопрос лицензии нужно уточнить.

## Видение интерфейса

Общее направление - ламповый рисованный интерфейс из цветных объёмных окон. Сиреневый фон в клетку, розовые и бирюзовые заголовки, кремовые рабочие области, жёлтые кнопки, тёмные контуры и жёсткие тени. Это оформление CSS, без обязательной библиотеки компонентов.

В полном замысле интерфейс содержит:

- Верхнюю полосу с названием редактора и версией.
- Панель команд New, Save, Load, Undo, Redo, Preview, Export HTML.
- Слева - библиотеку элементов.
- В центре - создаваемую страницу.
- Справа - свойства выбранного элемента.
- Снизу - строку состояния с числом элементов.

Будущие элементы: заголовок, текст, изображение, кнопка, разделитель, бегущая строка, GIF, декоративный счётчик, Under Construction и музыкальный проигрыватель.

Это ориентир для развития. Неактивные команды и пустые панели не добавляем только ради вида. Функции появляются по мере выполнения учебных задач.

## Лабораторная 4 - минимальный редактор

Цель - выполнить все критерии на «отлично» без полного конструктора.

### Объём

Два типа блоков: заголовок и обычный текст. Блоки располагаются вертикально, в порядке добавления.

Три области интерфейса:

1. Панель добавления - кнопки «Добавить заголовок» и «Добавить текст».
2. Редактор - поле текста и кнопка удаления каждого блока.
3. Предпросмотр - результат редактирования рядом с полями.

При узком экране области располагаются друг под другом. Предпросмотр виден постоянно: отдельный режим Preview пока не нужен.

Сценарий: открыть пустой редактор, добавить заголовок, изменить его текст, добавить текстовый блок, увидеть изменения в предпросмотре, удалить блок.

### Соответствие требованиям

| Требование | Реализация |
| --- | --- |
| Создание через npm create vite@latest | Используем уже созданную основу React + Vite |
| Декомпозиция | BlockToolbar, PageEditor, BlockEditor, PagePreview |
| useState | Хранит массив блоков страницы |
| props | Передаёт блоки и функции дочерним компонентам |
| Одно состояние влияет на несколько компонентов | Редактор и предпросмотр показывают один массив блоков |
| Callback меняет состояние родителя | Кнопки и поля вызывают переданные функции добавления, изменения и удаления |
| Алиасы | @ указывает на src |
| Собственный хук с useState | usePageBlocks хранит блоки и возвращает функции работы с ними |
| shared | Общий Button используется для добавления и удаления |

### Порядок шагов

1. Согласовать каркас и оформление. Заменить тему министерства на конструктор, убрать компоненты услуг. Результат - пустой редактор с понятными областями.
2. Добавить данные блоков, useState и кнопки добавления. Результат - заголовки и текстовые блоки появляются в редакторе.
3. Добавить редактирование, удаление и предпросмотр. Результат - одно состояние обновляет несколько компонентов, callbacks передаются через props.
4. Вынести логику в usePageBlocks. Результат - собственный хук с useState, поведение редактора не меняется.
5. Настроить @ и вынести Button в shared/ui. Результат - алиасы используются в импортах, общая кнопка используется повторно.
6. Проверить крайние случаи, сборку и код. Обновить README фактическим запуском и объяснением реализации.
7. Согласовать коммит, отправить ветку и открыть Pull Request в main. Слияние выполняет владелец вручную, ветка сохраняется.

Проверки: пустой редактор, добавление нескольких одинаковых типов, пустой текст, изменение нужного блока, удаление среднего и последнего блока, соответствие предпросмотра, стабильные key, работа на узком экране.

### Пока не делаем

API, авторизацию, сохранение, экспорт HTML, перетаскивание, изменение размеров, Undo/Redo, GIF, музыку и сложную панель свойств.

## Лабораторная 5 - каталог ретро-шаблонов через API

Продолжаем приложение лабы 4. Добавляем одну сущность проекта - шаблоны персональных страниц.

### Объём

Небольшой Node.js-сервер с маршрутом GET /api/templates возвращает заранее заданный список из 2-3 шаблонов. Например, «Фан-клуб кота», «Моя домашняя страница», «Сайт в разработке». Данные карточки: id, название, описание. База данных не нужна.

React делает реальный HTTP-запрос и показывает шаблоны карточками через map со стабильным key. Запрос запускается при открытии страницы. Есть загрузка, пустой ответ, ошибка и повторная попытка. Во время запроса кнопка повторной загрузки отключена.

Для требований лабы достаточно загрузить и показать каталог. Применение шаблона к странице согласуем отдельно: для оценки оно не требуется.

### Соответствие требованиям

| Требование | Реализация |
| --- | --- |
| Реальный HTTP-запрос | Axios обращается к GET /api/templates |
| useState, map и key | Данные хранятся в состоянии, TemplateCard получает props, key равен template.id |
| Загрузка и защита от повторного запуска | Индикатор загрузки и отключённая кнопка |
| Загрузка через useEffect | Запрос при открытии компонента, осознанные зависимости |
| Ошибка, повтор, пустой ответ | Отдельные сообщения и функция reload без перезагрузки страницы |
| Отдельный API-модуль | templatesApi.js содержит getTemplates |
| Единый клиент | shared/api/httpClient.js содержит Axios instance с baseURL и общими заголовками |
| Собственный хук | useTemplates хранит данные и статус, запускает запрос и возвращает reload |
| Интерсептор | Request-interceptor логирует HTTP-метод и адрес каждого запроса |

### Порядок шагов

1. После ручного merge лабы 4 создать lab-5-geocities от обновлённой main.
2. Согласовать данные шаблонов и создать один серверный маршрут. Проверить JSON-ответ.
3. Установить Axios, создать единый клиент, request-interceptor и API-модуль.
4. Создать useTemplates с useState, useEffect и reload. Не допускать повторяющихся запросов из-за неправильных зависимостей.
5. Добавить список шаблонов и отображение загрузки, ошибки и пустого ответа.
6. Проверить все состояния. Для защиты использовать задержку ответа, остановленный сервер и временный пустой список; отдельная панель симуляции не нужна.
7. Обновить инструкции запуска клиента и API, согласовать коммит и открыть Pull Request. Слияние вручную, ветка сохраняется.

На защите объясняем путь API - клиент Axios - API-модуль - хук - компонент. Показываем загрузку, ошибку, повтор и пустой список. Объясняем правила хуков, зависимости useEffect и назначение request-interceptor. Axios выбран для общего instance и интерсептора, требуемых на «отлично».

Не добавляем сохранение страниц на сервер, аккаунты, базу данных и публикацию сайтов.

## После лабораторных 4 и 5

По отдельному согласованию: изображения по URL, свойства элементов, изменение порядка, готовые шаблоны с применением, локальное сохранение, HTML-экспорт, ретроэлементы. Авторизация и серверное хранение - только при появлении соответствующей учебной задачи.

## Правила работы

- Каждый шаг сначала обсуждаем: цель, файлы и ожидаемый результат.
- После шага проверяем результат, разбираем код и согласуем правки.
- Коммиты редкие, по законченным частям работы. Состав и полное сообщение каждого коммита согласуются заранее.
- Автор коммитов - владелец проекта. Дополнительных авторов не добавляем.
- Лаба 4 выполняется в lab-4-geocities, лаба 5 - в lab-5-geocities.
- Pull Request открывается после проверки работы. Владелец мержит вручную. Ветки после merge сохраняются.
- В текстах используем обычный дефис `-`.

## Текущий запуск

После скачивания репозитория с исходниками и package.json:

```bash
npm install
npm run dev
```

Проверки:

```bash
npm run build
npm run lint
```

Команды относятся к имеющейся локальной основе Vite. Конструктор и API ещё не реализованы. Инструкции запуска API добавим в лабораторной 5.
